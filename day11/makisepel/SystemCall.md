## System Call (시스템 콜)

사용자 프로그램이 운영 체제의 기능을 사용하기 위해 커널에 서비스를 요청하는 것. 사용자 프로그램은 보안상의 이유로 입출력 장치 접근이나 프로세스 생성 등 특권 명령을 직접 수행할 수 없기 때문에 시스템 콜을 통해 운영 체제에 작업을 요청함

### 사용자 모드와 커널 모드

#### 1. 사용자 모드

사용자 프로그램의 코드를 실행하는 모드

- 일반적인 프로그램의 명령을 수행함
- 하드웨어 및 시스템 자원에 직접 접근할 수 없음
- 특권 명령을 직접 수행할 수 없음

#### 2. 커널 모드

운영 체제의 커널 코드를 실행하는 모드

- 시스템의 모든 자원에 접근 가능함
- 특권 명령을 수행할 수 있음
- 프로세스 관리, 메모리 관리, 입출력 등의 작업을 수행함

CPU는 **모드 비트**를 이용하여 현재 사용자 모드인지 커널 모드인지 구분함

### 필요한 이유

사용자 프로그램이 파일을 읽거나 디스크에 데이터를 저장하고, 새로운 프로세스를 생성하는 등의 작업을 수행하려면 운영 체제의 기능이 필요함. 하지만 이러한 작업은 특권 명령을 필요로 하기 때문에 사용자 프로그램이 직접 수행할 수 없으며, 시스템 콜을 통해 커널에 작업을 요청함

- 동작 과정
    
    사용자 프로그램 → 시스템 콜 요청 → 커널 모드 전환 → 운영 체제의 작업 수행 → 사용자 모드 복귀
    

### 동작 과정

디스크에서 데이터를 읽는 경우를 예로 들면 다음과 같이 동작함

1. 사용자 프로그램이 시스템 콜을 호출함
2. CPU가 커널 모드로 전환되고 운영 체제의 시스템 콜 처리 코드를 실행함
3. 운영 체제가 디스크 컨트롤러에 데이터 읽기를 요청함
4. 디스크 컨트롤러가 디스크에서 데이터를 읽어 버퍼에 저장함
5. 입출력이 완료되면 디스크 컨트롤러가 인터럽트를 발생시킴
6. 운영 체제가 입출력 완료를 처리함
7. 시스템 콜의 결과를 사용자 프로그램에 전달하고 사용자 모드로 복귀함

### 시스템 콜 처리

시스템 콜은 종류에 따라 각각 번호가 할당되어 있으며, 운영 체제는 시스템 콜 번호를 이용하여 어떤 작업을 요청했는지 확인함. 시스템 콜이 호출되면 시스템 콜 번호와 필요한 매개변수를 전달하고, 운영 체제는 해당 번호에 맞는 시스템 콜 처리 루틴을 실행함

ex) open() → 파일 열기, read() → 파일 읽기, write() → 파일 쓰기, fork() → 프로세스 생성

### 매개변수 전달

시스템 콜을 호출할 때 필요한 정보는 매개변수로 운영 체제에 전달함

1. CPU 레지스터 이용

매개변수를 CPU의 레지스터에 저장하여 전달함 → 전달해야 하는 매개변수의 수가 레지스터의 수보다 많을 경우 제한이 있음

2. 메모리 이용 

매개변수를 메모리에 저장하고 해당 메모리의 주소를 레지스터에 저장하여 전달함 → 많은 양의 매개변수를 전달할 수 있음

3. 스택 이용

매개변수를 프로그램의 스택에 저장하여 전달함→ 매개변수의 수나 크기에 대한 제한이 적음

### 유형 은 저번에 했지만 대충

1. 프로세스 제어

프로세스의 생성, 종료, 실행 등을 관리하는 기능 ex) fork(), exec(), exit()

2. 파일 조작

파일의 생성, 삭제, 열기, 읽기, 쓰기 등을 수행하는 기능 ex) open(), read(), write(), close()

3. 장치 관리

입출력 장치를 요청하거나 해제하고 장치에 데이터를 읽거나 쓰는 기능

4. 정보 유지

시스템의 시간, 날짜, 프로세스 정보 등의 정보를 가져오거나 설정하는 기능

5. 통신

프로세스 간 통신이나 네트워크 통신을 위한 연결 생성, 메시지 송수신 등의 기능 ex) Pipe, Socket 등을 이용한 프로세스 간 통신
