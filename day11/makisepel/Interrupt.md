## Interrupt (인터럽트)

인터럽트는 **CPU가 프로그램을 실행하는 중에 하드웨어나 소프트웨어가 CPU에게 특정 작업을 요청하는 것**이며, CPU는 현재 수행 중인 명령을 처리한 후 인터럽트 발생 여부를 확인하고 인터럽트가 발생한 경우 현재 작업을 잠시 중단한 뒤 운영 체제의 인터럽트 처리 루틴으로 이동하여 해당 작업을 처리함

#### 1. 하드웨어 인터럽트

하드웨어 장치가 CPU의 서비스를 요청하기 위해 발생시키는 인터럽트

ex) 키보드/마우스 입력, 디스크 입출력 완료, 타이머 등

하드웨어 장치가 인터럽트 신호를 보내면 CPU가 이를 확인하고 현재 실행 중인 작업을 잠시 중단한 뒤 해당 인터럽트를 처리함

#### 2. 소프트웨어 인터럽트

프로그램의 실행 과정에서 소프트웨어에 의해 발생하는 인터럽트

ex) exception과 시스템 콜이 있음

#### 1. Exception (예외)

프로그램이 정상적으로 수행할 수 없는 연산을 수행했을 때 발생하는 인터럽트 

ex) 0으로 나누기, 잘못된 메모리 접근 등

예외가 발생하면 운영 체제가 CPU의 제어권을 넘겨받아 해당 상황을 처리함

#### 2. 시스템 콜(System Call)

사용자 프로그램이 운영 체제의 서비스를 요청하기 위해 사용하는 인터페이스

사용자 프로그램은 직접 특권 명령을 수행할 수 없기 때문에 파일 입출력, 프로세스 생성 등의 작업이 필요한 경우 시스템 콜을 통해 커널에 작업을 요청함

### 발생 및 처리 과정

1. CPU가 프로세스 A의 명령을 실행한다
2. 하드웨어 또는 소프트웨어에 의해 인터럽트가 발생한다
3. CPU가 현재 실행 중인 작업의 상태를 저장한다
4. 인터럽트 벡터를 통해 해당 인터럽트의 처리 루틴 주소를 확인한다
5. Interrupt Handler를 실행하여 인터럽트를 처리한다
6. 인터럽트 처리가 끝나면 저장해 둔 프로세스 A의 상태를 복원한다
7. 중단되었던 작업을 이어서 수행한다

### Interrupt Vector

각 인터럽트에 대해 해당 인터럽트를 처리할 인터럽트 핸들러의 주소를 저장하고 있는 테이블

→ 인터럽트가 발생하면 인터럽트 종류에 맞는 처리 루틴의 주소를 찾는 데 사용

### Interrupt Handler

발생한 인터럽트를 실제로 처리하는 운영 체제의 코드, 인터럽트 서비스 루틴(Interrupt Service Routine)이라고도 하며 인터럽트 종류에 따라 수행해야 할 작업이 각각 정의되어 있음

ex) 디스크 입출력 완료 인터럽트 발생 → 해당 인터럽트의 핸들러 실행 → 입출력 작업 완료 처리
