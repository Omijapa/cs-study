# day22-2 쿠기와 세션의 차이

- 둘 다 HTTP의 무상태(Stateless) 특성을 보완하기 위해 사용
- HTTP는 이전 요청을 기억하지 않기 때문에, 로그인 상태 같은 정보를 유지하려면 쿠키나 세션이 필요

## 쿠키(Cookie)
- 데이터를 `클라이언트의 브라우저에 저장`하는 방식

```text
로그인 요청
→ 서버가 쿠키를 발급
→ 브라우저가 쿠키 저장
→ 이후 요청마다 쿠키를 서버로 전송
```

예시:
```http
Set-Cookie: userId=10
```

브라우저는 이후 요청에서 다음과 같이 쿠키를 보냄
```http
Cookie: userId=10
```

### 특징
- 클라이언트에 저장
- 서버 요청 시 자동으로 함께 전송
- 만료 시간 설정 가능, 브라우저 종료해도 유지되도록 설정 가능
- 사용자가 내용을 확인하거나 수정 가능 -> 민감한 정보 저장에는 부적절

### 용도
- 자동 로그인
- 장바구니
- 사용자 설정
- 최근 본 상품 ..


## 세션(Session)
- 사용자 정보를 `서버에 저장`하는 방식
- 서버는 각 사용자에게 고유한 `세션 ID`를 발급
- 실제 데이터는 서버에 저장함

```text
클라이언트 로그인
→ 서버가 세션 생성
→ 서버가 세션 ID 발급
→ 브라우저가 세션 ID를 쿠키에 저장
→ 이후 요청마다 세션 ID 전송
→ 서버가 세션 ID로 사용자 정보 조회


예:

브라우저 쿠키
sessionId=abc123

서버
abc123 → 사용자 10번, 로그인 상태
```

## 차이점 정리

| 구분    | 쿠키               | 세션                          |
| ----- | ---------------- | --------------------------- |
| 저장 위치 | 클라이언트 브라우저       | 서버                          |
| 저장 내용 | 데이터 자체           | 실제 데이터는 서버, 클라이언트에는 세션 ID   |
| 보안    | 상대적으로 낮음         | 상대적으로 높음                    |
| 서버 부담 | 적음               | 사용자가 많으면 저장 공간 부담 증가        |
| 속도    | 서버 조회가 적어 비교적 빠름 | 서버에서 세션을 조회해야 함             |
| 유지 기간 | 만료 시간을 설정할 수 있음  | 로그아웃, 만료, 서버 종료 등에 따라 삭제 가능 |
| 용량    | 비교적 작음           | 서버가 허용하는 범위에서 관리            |
| 주요 용도 | 설정, 장바구니, 자동 로그인 | 로그인 상태, 인증 정보               |



쿠키: 정보를 브라우저에 저장
세션: 정보를 서버에 저장하고, 브라우저에는 세션 ID만 저장

## 참고

### 면접용
```text
쿠키는 클라이언트에 데이터를 저장하는 방식이고, 세션은 서버에 사용자 상태를 저장한 뒤 클라이언트에는 세션을 식별하기 위한 세션 ID만 전달하는 방식입니다.
쿠키는 서버 부담이 적지만 보안에 취약할 수 있고, 세션은 상대적으로 안전하지만 서버 메모리를 사용한다는 차이가 있습니다.

```
