# Day 22 - REST란?, 쿠키와 세션의 차이

# REST

REST(Representational State Transfer)는 웹의 자원(Resource)을 URI로 식별하고, HTTP 메서드를 이용해 자원을 조작하는 아키텍처 스타일이다.

RESTful은 REST 아키텍처를 구현하는 웹 서비스를 나타낸 것으로 REST 원리를 따르는 시스템을 RESTful이라는 용어로 지칭한다.

### 핵심 개념

1. Resource(자원) : 서버가 관리하는 데이터
2. URI : 자원을 식별하는 주소
3. HTTP Method : 자원에 대한 행위를 표현(GET, POST, PUT, DELETE 등)
4. Representation(표현) : 자원의 실제 데이터(JSON, XML 등)

### 특징(제약조건)

1. Client-Server : 클라이언트와 서버의 역할을 분리한다
2. Stateless : 서버는 클라이언트의 이전 요청 상태를 저장하지 않는다
3. Cacheable : 응답을 캐시하여 성능을 향상시킬 수 있다
4. Uniform Interface : URI와 HTTP 메서드를 일관성 있게 사용한다
5. Layered System : 프록시, 로드밸런서, API Gateway 등 중간 계층을 둘 수 있다
6. Code on Demand(optional) : 필요 시 클라이언트에 코드를 전달할 수 있다

# 쿠키 vs 세션

## 쿠키

데이터를 클라이언트에 저장하는 방식이다. 서버 부담이 적은 대신 보안이 상대적으로 약하다. (변조/탈취 위험)

#### 동작 과정

1. 서버가 쿠키를 생성하여 브라우저에 저장한다
2. 브라우저는 이후 모든 요청마다 쿠키를 함께 전송한다
3. 서버는 쿠키 값을 읽어 사용자를 식별하거나 정보를 활용한다

#### 종류

1. 세션 쿠키 : 브라우저 종료 시 자동 삭제, 별도의 만료 시간 없음
2. 영속 쿠키 : 브라우저를 종료해도 남아 있고, 만료 시간을 지정함

#### 속성

1. HttpOnly : Javascript에서 접근 불가능, XSS 공격으로부터 쿠키 탈취 방지
2. Secure : HTTPS에서만 전송
3. SameSite : CSRF(사이트 간 요청 위조) 방지를 위한 속성

## 세션

데이터를 서버에 저장하는 방식이다. 서버 메모리를 사용한다는 단점이 있지만, 로그인 정보와 같은 민감한 데이터를 관리하기에 적합하다. 브라우저 쿠키에 세션ID 정보만 저장한다.

#### 동작 과정

1. 사용자가 로그인한다
2. 서버가 세션을 생성하고 사용자 정보를 서버 메모리에 저장한다
3. 서버는 세션 ID만 브라우저의 쿠키에 저장한다 (JSESSIONID=세션ID)
4. 이후 요청마다 브라우저는 세션 ID를 전송한다
5. 서버는 세션 ID로 사용자 정보를 조회한다

#### 저장 방식

1. Session In Memory : 빠름, 서버 재시작 시 세션 삭제, 단일 서버에서만 가능
2. Redis Session : 서버 여러 대에서도 공유 가능, 분산 환경에서 씀
3. DB Session : 가장 느림, 잘 안씀
