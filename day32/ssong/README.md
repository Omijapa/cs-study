# Day 32 - 정규화, 저장 프로시저

# 정규화

## 제1정규형

- 모든 속성 값이 원자 값으로만 구성
- 즉, 하나의 속성 값에 여러 개의 값이 들어갈 수 없음

## 제2정규형

- 제1정규형 + 부분 함수 종속을 모두 제거한 상태
- 즉, 모든 속성이 기본키 전체에 완전 함수 종속 상태
- 예를 들어 기본키가 (학생ID, 과목ID)인데 학생 이름이 학생ID에만 종속되는 것을 부분 함수 종속이라고 함

## 제3정규형

- 제2정규형 + 이행 함수 종속을 모두 제거한 상태
- 예를 들어 학생ID → 학과ID → 학과명에서 학과명이 학생ID에 직접 종속되는 것이 아닌 학과ID를 거쳐 결정되는 것을 이행적 함수 종속이라고 함

## BCNF

- 제3정규형 + 모든 결정자가 후보키여야 함
- 즉, 모든 함수 종속 X → Y에서 결정자 X가 후보키여야 함

## 제4정규형

- BCNF + 다치 종속을 제거한 정규형
- 예를 들어 한 학생이 여러 개의 취미와 여러 개의 자격증을 독립적으로 가지고 있을 때, 취미와 자격증은 서로 관련이 없는데 (이름, 취미, 자격증)을 컬럼으로 하는 테이블을 만들어버리면 취미와 자격증의 조합만큼 불필요한 행이 추가됨. 따라서, (이름, 취미)와 (이름, 자격증)으로 테이블을 분리하여 불필요한 조합을 제거해야 함

## 제5정규형

- 제4정규형 + 불필요한 조인 종속을 제거한 정규형 (모든 조인 종속이 후보키에 의해 이루어지는지 확인하기)
- 조인 종속은 하나의 테이블을 여러 개의 테이블로 분해했을 때, 그 테이블들을 다시 JOIN하면 원래 테이블을 정확하게 복원할 수 있는 관계를 의미함

## 반정규화

정규화된 테이블의 구조를 의도적으로 통합하거나 중복을 허용하여 데이터베이스의 성능을 향상시키는 과정이다. 과도한 조인으로 발생하는 성능 저하를 막기 위해 사용되지만, 데이터의 일관성이 깨질 위험이 있다.

테이블 통합, 분할(수평/수직), 중복 컬럼 추가, 중복 테이블 생성, 파생 컬럼 추가 등의 기법이 있다.

# 저장 프로시저

- 데이터베이스에 미리 저장해두고 필요할 때 호출해서 실행하는 SQL문들의 집합
- 즉, 자주 사용하는 SQL 쿼리들을 하나의 프로그램처럼 DB에 저장해두고 호출하는 것이다

## 사용하는 이유

예를 들어 회원 탈퇴를 처리하기 위해 다음 SQL을 실행해야 한다고 하자

1. 회원 정보 삭제
2. 회원 주문 정보 처리
3. 포인트 처리
4. 로그 기록
5. 관련 데이터 삭제

어플리케이션에서 직접 처리하려면 5개의 쿼리가 개별적으로 전송되는데 이를 저장 프로시저로 묶으면 복잡한 DB 작업을 하나의 단위로 묶을 수 있다

## 장점

1. 성능 향상
   1. 여러 개의 쿼리를 한번에 실행할 수 있음
   2. 캐시를 활용하므로 속도가 빠름
   3. 쿼리를 쓸 때마다 구문을 분석해 실행 가능한 코드로 컴파일하는데 드는 비용을 없앨 수 있음
2. 유지 보수
   1. 개발 언어에 비의존적
   2. 변경 사항이 있을 때 프로시저 내부만 수정하면 된다.
3. 트래픽 감소
   1. 클라이언트에서 서버로 쿼리의 모든 텍스트가 전송될 경우 네트워크 부하가 심한데, 저장 프로시저를 사용하면 프로시저의 이름, 매개변수 등만 전송하면 되기에 부하를 크게 줄일 수 있음
4. 보안
   1. 저장 프로시저에게만 접근 권한을 주어 일반 사용자의 테이블 접근을 제한할 수 있음

## 단점

1. 확장 어려움
   1. DB 수를 늘리거나 교체하는 것이 어려움
2. 데이터 분석의 어려움
   1. 하나의 저장 프로시저가 여러 곳에서 사용될 경우 수정의 영향을 분석하기 어려움
   2. 배포, 버전 관리 등에 대한 이력 관리가 어려움
   3. 문제가 생겼을 때 이슈를 추적하기가 어려움 (별도의 에러 테이블이 필요함)
3. 낮은 처리 성능
   1. 문자, 숫자열 연산에 저장 프로시저를 사용할 경우 오히려 C, Java 보다 느림
