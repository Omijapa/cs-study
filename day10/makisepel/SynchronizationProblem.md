## Synchronization Problem(동기화 문제)

동기화는 **여러 프로세스나 스레드가 공유 자원에 동시에 접근하여 발생할 수 있는 문제를 방지하기 위한 기법**이며, 여러 스레드의 실행 순서를 조정하거나 한 번에 공유 자원에 접근할 수 있는 스레드의 수를 제한함

### 스레드 동기화

#### 1. 실행 순서의 동기화

스레드의 실행 순서를 정의하고 정해진 순서대로 실행되도록 하는 것

→ 특정 스레드의 작업이 끝난 후 다른 스레드가 작업을 수행해야 하는 경우 사용

#### 2. 메모리 접근의 동기화

여러 스레드가 공유 메모리에 동시에 접근하지 못하도록 하는 것

→ 실행 순서 자체가 중요한 것이 아니라 한 순간에 하나의 스레드만 해당 자원에 접근하도록 하는 것이 목적

### 동기화가 필요한 이유

여러 스레드가 하나의 공유 자원에 동시에 접근하면 실행 순서에 따라 결과가 달라질 수 있음

ex) 여러 스레드가 하나의 변수에 동시에 값을 증가시키는 경우

count++는 단순히 한 번에 실행되는 것이 아니라 값을 읽고/ 증가시키고 / 다시 저장하는 과정으로 이루어지기 때문에 여러 스레드가 동시에 실행하면 같은 값을 읽어 예상보다 작은 결과가 저장될 수 있음. 이처럼 여러 스레드가 공유 자원에 동시에 접근하여 실행 결과가 달라지는 문제를 **Race Condition**이라고 함

## 임계 영역

여러 프로세스나 스레드가 동시에 접근해서는 안 되는 공유 자원을 사용하는 코드 영역이며, 임계 영역에 여러 스레드가 동시에 접근하면 데이터의 일관성이 깨질 수 있기 때문에 한 번에 하나의 스레드만 접근하도록 동기화가 필요함

### 문제 조건

#### 1. 상호 배제

하나의 프로세스나 스레드가 임계 영역을 실행하고 있다면 다른 프로세스나 스레드는 해당 임계 영역에 접근할 수 없어야 함 → 한 순간에 하나의 스레드만 공유 자원을 사용할 수 있어야 함

#### 2. 진행

임계 영역을 실행하고 있는 프로세스나 스레드가 없다면 임계 영역에 진입하려는 프로세스나 스레드 중 하나가 진입할 수 있어야 함 → 임계 영역에 들어갈 수 있는데도 무한히 기다리는 상황이 발생하면 안 됨

#### 3. 한정된 대기

프로세스나 스레드가 임계 영역에 진입하기 위해 요청한 이후 무한히 대기하지 않도록 해야 함 → 다른 스레드가 계속해서 먼저 실행되어 특정 스레드가 영원히 대기하는 상황을 방지함

## 동기화 기법

동기화 기법은 크게 **사용자 모드에서 동작하는 방법**과 **커널의 도움을 받는 방법**으로 나눌 수 있음

### 1. 사용자 모드 동기화

커널 모드로 전환하지 않고 사용자 모드에서 처리하는 동기화 방법 

→ 커널 모드로 전환하는 비용이 없어 상대적으로 빠르지만 사용할 수 있는 기능에 제한이 있음

#### 2. 임계 영역 기반 동기화

하나의 스레드만 임계 영역에 접근할 수 있도록 Lock을 이용하여 접근을 제어함

→ 다른 스레드가 Lock을 가지고 있으면 Lock이 반환될 때까지 대기하고 Lock을 얻은 후 임계 영역에 접근함

#### 인터락 함수

하나의 변수에 대한 연산이 다른 스레드와 동시에 실행되지 않도록 원자적으로 처리하는 방법

→ 값을 읽고 수정하는 과정이 중간에 다른 스레드에 의해 방해받지 않도록 하며 사용자 모드에서 동작하기 때문에 커널 모드 동기화보다 빠르게 동작할 수 있음

## 커널 모드 동기화

운영 체제에서 제공하는 동기화 기능을 이용하는 방법 ex) ****Semaphore, Mutex, Monitor

→ 필요한 경우 커널 모드로 전환하여 스레드를 대기시키거나 깨우는 등의 작업을 수행

### Semaphore

공유 자원에 동시에 접근할 수 있는 프로세스나 스레드의 수를 Counter로 관리하는 동기화 기법,

Counter의 값은 현재 공유 자원에 접근할 수 있는 스레드 또는 프로세스의 수를 의미함

- Counter > 0 → 자원에 접근 가능
- 자원 접근 시 Counter 감소
- 자원 사용 완료 시 Counter 증가
- Counter = 0 → 자원에 접근할 수 없어 대기

#### Semaphore의 종류

- Binary Semaphore : Counter가 0 또는 1만 가짐
- Counting Semaphore : Counter가 2 이상인 여러 값을 가질 수 있음

ex) 화장실 칸이 4개이고 열쇠가 4개라면 최대 4명까지 동시에 화장실을 사용할 수 있으며 4명이 모두 사용 중이면 다음 사람은 빈자리가 생길 때까지 대기함

→ 화장실 빈자리의 수를 Semaphore Counter라고 생각할 수 있음

참고로, Semaphore는 소유권이 존재하지 않음

→ Semaphore를 획득한 스레드가 아닌 다른 스레드도 Semaphore를 해제할 수 있음

### Mutex

하나의 공유 자원에 하나의 프로세스나 스레드만 접근할 수 있도록 하는 동기화 기법,

Lock과 Unlock을 이용하여 공유 자원에 대한 접근을 제어함

- Lock 획득 시 공유 자원에 접근
- 다른 스레드가 Lock을 가지고 있을 때는 대기
- 작업 완료 → Unlock
- 다른 스레드가 Lock 획득

Mutex는 Lock에 대한 소유권이 존재하며 Lock을 획득한 스레드만 Lock을 해제할 수 있음

⇒  예를 들어 화장실이 하나이고 열쇠가 하나인 경우 화장실을 사용하려면 열쇠를 가지고 있어야 하며 다른 사람은 열쇠가 반환될 때까지 기다려야 하므로

- 화장실 → 공유 자원
- 화장실 열쇠 → Mutex
- 열쇠를 가진 사람 → 공유 자원을 사용하는 스레드
- 열쇠를 기다리는 사람 → 대기 중인 스레드

로 볼 수 있따

### Monitor

공유 자원과 공유 자원에 접근하는 연산을 하나로 묶고 동시 접근을 제어하는 동기화 구조,

Mutex와 Condition Variable 등을 이용하여 하나의 스레드만 공유 자원에 접근하도록 하며 조건에 따라 스레드를 대기시키거나 다시 실행할 수 있음
