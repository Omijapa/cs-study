## Page Replacement Algorithm (페이지 교체)

운영체제는 주기억장치보다 더 큰 용량의 프로그램을 실행하기 위해 프로그램의 일부만 주기억장치에 적재하여 사용하는, 가상 메모리 기법을 사용하는데 필요한 페이지만 적재하더라도 메모리가 가득 차게 될 수 있다. 따라서 새로운 페이지를 추가할 경우 기존의 페이지를 선택하여 OUT시킬 수 있도록 하는 선택 알고리즘이 필요하다.

### 교체 과정

Page Fault(필요로 하는 페이지가 적재되지 않은 경우)가 발생했을 때 요청된 페이지를 메모리에 적재해야 하지만 빈 프레임이 없는 경우 기존에 메모리에 올라와 있는 페이지 중 하나를 선택하여 디스크로 내보내고 새로운 페이지를 적재함

⇒ 페이지 교체 알고리즘은 이때 어떤 페이지를 교체할지 결정하며, Page Fault 발생 빈도 최소화를 목표로 함

### FIFO (First IN First Out, 선입선출)

메모리에 먼저 적재된 페이지를 먼저 교체하는 방식임

- 구현 간단
- 페이지의 실제 사용 여부를 고려하지 않음
- 페이지 프레임 수를 늘렸는데도 Page Fault 수가 증가하는 Belady's Anomaly가 발생할 수 있음
    
    → 프레임 수가 4고 초기 상태에 어떤 페이지도 없을 경우, 해당 프레임들을 채우는 과정에서 Page Fault 발생 
    

### Optimal

앞으로 가장 오랫동안 사용되지 않을 페이지를 교체하는 방식임

- Page Fault 발생률 가장 낮음
- 미래의 페이지 참조를 미리 알아야 하기 때문에 실제 시스템에서 구현하기 어려움
- 다른 페이지 교체 알고리즘의 성능을 비교하는 기준으로 사용함

### LRU (Least Recently Used)

가장 오랫동안 사용되지 않은 페이지를 교체하는 방식이며, 최근에 사용하지 않은 페이지는 앞으로도 사용하지 않을 가능성이 높다는 점을 이용함

- 과거의 참조 기록을 이용하기 때문에 실제 시스템에서 사용할 수 있음
- 효율적인 페이지 교체 방식 중 하나

### LFU (Least Frequntly Used)

페이지의 과거 참조 횟수가 가장 적은 페이지를 교체하는 방식이며, 페이지가 얼마나 자주 사용되었는지를 기준으로 하기 때문에 최근의 사용 여부를 충분히 반영하지 못할 수 있으며, 참조 횟수를 관리해야 하므로 LRU보다 구현이 복잡함

### Clock

LRU를 근사하여 최근에 사용되지 않은 페이지를 빠르게 찾는 방식임

참조 비트와 변형 비트를 이용하여 페이지의 최근 사용 여부와 수정 여부를 판단함

- 참조 비트 : 페이지가 참조되면 1로 설정됨
- 변형 비트 : 페이지의 내용이 변경되면 1로 설정됨

LRU처럼 정확한 최근 사용 순서를 관리하지 않아 오버헤드가 적고, 하드웨어의 지원을 받아 효율적으로 페이지를 교체할 수 있음
