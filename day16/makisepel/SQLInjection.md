## SQL Injection

사용자가 입력한 값을 SQL 쿼리에 그대로 넣을 때, 입력값이 데이터가 아닌 SQL 명령으로 해석되어 원래 의도와 다른 쿼리가 실행되는 공격 기법

ex) 로그인할 때 ID 대신 SQL 구문을 넣는다던가 등등

### 발생 원리

웹 애플리케이션에서 사용자의 입력값을 이용해 SQL을 문자열로 만들어 실행하는 경우 애플리케이션 내부에서는 입력값을 SQL 조건에 포함시켜 데이터베이스에 전달할 수 있는데, 

이때 입력값과 SQL 구문이 제대로 분리되어 있지 않으면 공격자가 SQL의 조건이나 구조를 변경할 수 있음

### 공격 방식

#### 1. 인증 우회

로그인과 같이 사용자의 입력값을 이용해 조건을 검사하는 과정에서 발생

공격자가 입력값에 SQL 조건을 추가하여 원래의 비밀번호 확인 조건이 정상적으로 검사되지 않도록 만들 수 있음

→ 실제 비밀번호를 알지 못하더라도 로그인 조건을 만족하는 것처럼 처리될 수 있ㅇ므

#### 2. 데이터 조회

SQL Injection을 통해 원래 애플리케이션에서 제공하지 않는 데이터까지 조회하도록 SQL의 조건을 변경할 수 있음

공격이 성공하면 다른 사용자의 정보나 테이블에 저장된 데이터가 노출될 수도 있음

#### 3. 데이터 조작

조회뿐만 아니라 데이터의 수정이나 삭제와 관련된 SQL이 실행되도록 유도할 수도 있음

따라서 공격이 성공하면 데이터가 변조되거나 삭제되는 등 데이터베이스 자체에 피해가 발생할 수 있음

#### 4. 데이터베이스 정보 확인

의도적으로 SQL 오류를 발생시키거나 SQL의 동작 결과를 확인하면서 데이터베이스의 테이블이나 컬럼 구조 등을 추측할 수 있음

이러한 정보를 이용해 추가적인 SQL Injection 공격을 시도할 수 있음

### 방어 방법

#### 1. Prepared Statement 사용

SQL 문장과 사용자가 입력하는 값을 분리하는 방법

→ 입력값을 SQL 문법으로 해석하지 않고 하나의 데이터로 처리하기 때문에 SQL Injection을 방지하는 가장 대표적인 방법

#### 2. 입력값 검증

사용자가 입력할 수 있는 값의 형식이나 범위를 미리 정해두고, 예상하지 못한 입력을 차단함

→ 특정 문자만 찾아서 제거하는 방식만으로 SQL Injection을 완전히 방어하기는 어렵긴 하다

#### 3. 최소 권한 사용

웹 애플리케이션이 데이터베이스에 접근할 때 필요한 권한만 부여함

→ SQL Injection이 발생하더라도 해당 계정이 접근할 수 있는 데이터와 수행할 수 있는 작업을 제한하여 피해를 줄일 수 있음

#### 4. 오류 정보 제한

데이터베이스의 상세한 오류 내용을 사용자에게 그대로 보여주지 않도록 함

→ 오류 메시지에 테이블명이나 컬럼명 등의 정보가 포함되면 공격자가 데이터베이스 구조를 파악하는 데 이용할 수 있음
