## Key

Relation에서 Tuple을 유일하게 식별하거나 다른 Relation과의 관계를 표현하기 위해 사용하는 Attribute의 집합

ex) 학생, 수강 테이블을 아래와 같이 예시로 두면 (교보재 참조)

- 학생

| 학번 | 주민번호 | 성명 | 성별 |
| --- | --- | --- | --- |
| 1001 | 810429-1231457 | 김형석 | 남 |
| 1002 | 800504-1546781 | 김현천 | 남 |
| 1002 | 811216-2547842 | 류기선 | 여 |
| 1003 | 910322-1233445 | 홍영선 | 여 |
- 수강

| 학번 | 과목명 |
| --- | --- |
| 1001 | 영어 |
| 1001 | 전산 |
| 1002 | 영어 |
| 1003 | 수학 |
| 1004 | 영어 |
| 1004 | 전산 |

### 1. Candidate Key (후보키)

Relation의 Tuple을 유일하게 식별할 수 있는 Attribute의 부분 집합이며, 유일성과 최소성을 모두 만족해야 함

- 유일성 : 하나의 Key 값으로 하나의 Tuple을 구분할 수 있음
- 최소성 : Tuple을 식별하는 데 필요한 최소한의 Attribute로 구성됨

후보키 중에서 Primary Key로 선택할 수 있으며, 하나의 Relation은 여러 개의 후보키를 가질 수 있음

### 2. Primary Key (기본키)

후보키 중에서 Relation의 Tuple을 대표하여 식별하기 위해 선택한 Key

기본키는 유일성을 만족해야 하며 

1. NULL 값을 가질 수 없고 2. 중복된 값을 가질 수 없음

후보키가 여러 개 존재하는 경우 그중 하나를 기본키로 선택함

### 3. Alternate Key (대체키)

후보키 중에서 기본키로 선택되지 않은 나머지 후보키를 의미함

ex) 학생 테이블에서 학번과 주민번호가 모두 후보키이고 학번을 기본키로 선택했다 → 주민번호가 대체키

### 4. Super Key (슈퍼키)

Relation의 Tuple을 유일하게 식별할 수 있는 Attribute의 집합이며, 유일성은 만족하지만 최소성은 만족하지 않아도 됨

ex) 학생 테이블에서 학번이 Tuple을 유일하게 식별할 수 있다면 학번 + 이름과 같이 불필요한 Attribute가 추가된 경우에도 슈퍼키가 될 수 있음

후보키는 최소성을 만족하는 슈퍼키

### 5. Foreign Key (외래키)

한 Relation의 Attribute가 다른 Relation의 기본 키를 참조할 때 사용하는 Key임

외래키를 통해 서로 다른 Relation 사이의 참조 관계를 표현하며, 외래키의 값은 참조하는 릴레이션의 기본키에 존재하는 값이어야 하며 이를 통해 Relation 간의 참조 무결성을 유지할 수 있음

ex) 학생 Relation의 학번이 기본키이고 수강 Relation의 학번이 이를 참조한다면

⇒ 학생의 학번은 기본키, 수강의 학번은 외래키가 됨

### Key의 관계

- Super Key 중에서 최소성을 만족하는 Key가 Candidate Key
- Candidate Key 중 하나를 선택한 것이 Primary Key
- 선택되지 않은 Candidate Key가 Alternate Key
