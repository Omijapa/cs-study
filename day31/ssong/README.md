# Day 31 - 파일 시스템

# 파일 시스템

**파일** : 보조기억장치에 저장된 관련 데이터의 논리적 단위로 이름을 통해 식별되는 저장 단위

**파일 속성(메타데이터)** : 파일의 내용이 아닌 파일을 관리하기 위한 각종 정보(이름, 유형, 저장된 위치, 크기, 접근 권한, 소유자 등)

**파일 시스템** : 운영체제가 저장장치에 있는 파일과 디렉터리를 저장·관리하고 접근할 수 있도록 하는 시스템. 파일의 데이터와 메타데이터, 디렉터리 구조 등을 관리하며 파일 생성, 삭제, 읽기, 쓰기 등의 기능을 제공한다

한 마디로, 파일 시스템은 파일을 저장장치에 어떻게 저장하고 관리할 것인가에 대한 체계!

# 접근 방법

### 1. 순차 접근

가장 단순한 방법으로, 파일의 정보가 레코드 순서대로 처리된다 (카세트테이프를 사용하는 방식과 동일)

현재 위치에서 읽거나 쓰면 offset이 자동으로 증하고, 뒤로 돌아가기 위해서는 되감기가 필요함

### 2. 직접 접근

파일의 레코드를 임의의 순서로 접근할 수 있다 (LP 판을 사용하는 방식과 동일)

읽기와 쓰기의 순서에 제약이 없고 현재 위치를 유지할 수 있다면 이를 통해 순차 접근 기능도 구현 가능

### 3. 인덱스 접근

파일에서 레코드를 찾기 위해 인덱스를 먼저 찾고 대응되는 포인터를 얻는다. 이를 통해 파일에 직접 접근하여 원하는 데이터를 얻을 수 있다

# 디렉터리

파일의 메타데이터 중 일부를 보관하고 있는 일종의 특별한 파일이다

해당 디렉터리에 속한 파일 이름과 속성들을 포함하고 있고 다음 기능들을 제공한다

1. 파일 찾기
2. 파일 생성
3. 파일 삭제
4. 디렉터리 나열
5. 파일 이름 변경
6. 파일 시스템 순회

## 디렉터리의 논리적 구조

### 1. 1단계 디렉터리

모든 파일들이 디렉터리 밑에 존재하는 형태. 파일들은 unique한 이름을 갖는다

![](https://noep.github.io/2016/02/23/10th-filesystem/10.5.png)

### 2. 2단계 디렉터리

각 사용자 별로 별도의 디렉터리를 갖는 형태. 서로 다른 사용자가 같은 이름의 파일을 가질 수 있음

![](https://noep.github.io/2016/02/23/10th-filesystem/10.6.png)

### 3. 트리 구조 디렉터리

사용자들이 자신의 서브 디렉터리를 만들어 파일을 구성하는 형태. 하나의 루트 디렉터리를 가지며 모든 파일은 고유한 경로(절대/상대 경로)를 가짐. 이를 통해 효율적인 탐색과 그룹화가 가능함

bit를 사용하여 파일인지 디렉터리인지를 구분(0이면 파일, 1이면 디렉터리)

![](https://noep.github.io/2016/02/23/10th-filesystem/10.7.png)

### 4. 비순환 그래프 디렉터리

디렉터리들이 서브 디렉터리들과 파일을 공유할 수 있도록 한다 (트리 구조 디렉터리를 일반화한 형태)

![](https://noep.github.io/2016/02/23/10th-filesystem/10.8.png)

### 5. 일반 그래프 디렉터리

순환을 허용하는 그래프 구조이다.

순환이 허용되니 무한 루프에 빠질 위험이 있어 하위 디렉터리가 아닌 파일에 대한 링크만 허용하거나 GC를 통해 전체 파일 시스템을 순회하고 접근 가능한 모든 것을 표시함

![](https://noep.github.io/2016/02/23/10th-filesystem/10.9.png)
