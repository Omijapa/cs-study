## Process vs Thread + Context Switching

### Process

프로세스는 **실행 중인 프로그램**이다. 운영 체제는 프로그램을 실행하면 하나의 프로세스를 생성하며, 각 프로세스는 독립적인 메모리 공간을 가진다

메모리 구조

- Code(Text) : 실행 코드 저장
- Data : 전역 변수 및 정적 변수 저장
- Heap : 동적 메모리 저장
- Stack : 함수 호출 및 지역 변수 저장

### Thread

스레드는 **프로세스 내에서 실제 작업을 수행하는 실행 단위**이다. 하나의 프로세스는 여러 개의 스레드를 가질 수 있으며, Code, Data, Heap 영역을 공유하고 Stack은 각각 독립적으로 사용한다

### Process vs Thread

|  | Process | Thread |
| --- | --- | --- |
| 정의 | 실행 중인 프로그램 | 프로세스 내부 실행 단위 |
| 메모리 | 독립적인 메모리 공간 사용 | Code, Data, Heap 공유 |
| 생성 비용 | 큼 | 작음 |
| Context Switching 비용 | 큼 | 작음 |
| 통신 | 프로세스 간 통신(IPC) 필요 | 메모리 공유로 데이터 교환 쉬움 |
| 안정성 | 하나의 프로세스 오류가 다른 프로세스에 영향을 주지 않음 | 하나의 스레드 오류가 전체 프로세스에 영향을 줄 수 있음 |
| 장점 | 독립적인 메모리 공간 사용, 안정성이 높음 | 생성 및 종료 비용이 적고 병렬 처리에 적합함 |
| 단점 | 생성 비용이 크고 IPC가 필요함 | 동기화가 필요하며 Race Condition이 발생할 수 있음 |

### Context Switching

현재 실행 중인 프로세스나 스레드의 상태를 저장하고 다른 Task의 상태를 복원하여 CPU의 실행 대상을 변경하는 과정

- 현재 Task의 상태를 PCB 또는 TCB에 저장함
- 다음 Task의 상태를 CPU 레지스터에 복원함
- 이전에 실행하던 지점부터 작업을 이어서 수행함

프로세스는 메모리를 독립적으로 사용하기 때문에 Context Switching 비용이 크고, 스레드는 메모리를 공유하기 때문에 상대적으로 비용이 작음
