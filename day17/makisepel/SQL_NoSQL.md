## SQL vs NoSQL

SQL과 NoSQL은 데이터를 저장하고 관리하는 방식이 다른 데이터베이스이며, 어떤 것이 더 좋은지가 아니라 데이터의 구조와 사용 목적에 따라 선택

### SQL

관계형 데이터베이스에서 데이터를 테이블 형태로 저장하고 관리하는 방식

데이터는 미리 정의된 스키마에 따라 저장하며, 여러 테이블이 서로 관계를 맺어 데이터를 관리함

- 테이블과 컬럼의 구조가 명확함
- 데이터 간의 관계를 이용하여 관리, 여러 테이블의 데이터를 함께 조회할 수 있음

**장점**

- 명확한 스키마로 데이터 구조를 관리하기 쉬움
- 데이터 무결성을 유지하기 좋음
- 데이터 중복을 줄이기 좋음
- 복잡한 관계를 가진 데이터를 조회하기 좋음

**단점**

- 스키마가 정해져 있어 구조 변경이 상대적으로 어려움
- 테이블 간 관계가 복잡해질수록 JOIN이 많아질 수 있음
- 대규모 분산 환경에서 수평 확장이 상대적으로 복잡함

**사용하는 경우**

- 데이터 간의 관계가 중요한 경우
- 데이터 무결성이 중요한 경우
- 데이터 구조가 명확하고 자주 변경되지 않는 경우
- 여러 테이블의 관계를 이용한 조회가 필요한 경우

### NoSQL

관계형 데이터베이스의 테이블 구조를 따르지 않고 다양한 형태로 데이터를 저장하는 방식

대표적으로 문서형 데이터베이스가 있으며, JSON과 유사한 형태의 문서로 데이터를 저장함

- 고정된 스키마가 없어 데이터 구조가 유연함
- 서로 다른 구조의 데이터를 저장할 수 있음
- 필요한 데이터를 하나의 문서에 함께 저장하기 쉬움
- JOIN 대신 데이터를 함께 저장하거나 복제하는 방식을 많이 사용함

**장점**

- 스키마가 유연하여 데이터 구조 변경이 쉬움
- 필요한 데이터를 하나의 문서에 저장하여 조회하기 편함
- 대규모 데이터를 여러 서버에 분산하기 유리함
- 수평 확장에 유리함

**단점**

- 데이터가 중복될 수 있음
- 중복된 데이터를 수정할 경우 여러 곳을 함께 수정해야 할 수 있음
- 데이터 구조를 애플리케이션에서 관리해야 하는 경우가 있음
- 복잡한 관계를 가진 데이터를 처리하기에는 적합하지 않을 수 있음

**사용하는 경우**

- 데이터 구조가 자주 변경되는 경우
- 대량의 데이터를 분산하여 처리해야 하는 경우
- 읽기 작업이 많고 빠른 조회가 중요한 경우
- 하나의 문서에 관련 데이터를 함께 저장하는 것이 적합한 경우
