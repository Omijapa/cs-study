## Anomaly (이상 현상)

하나의 테이블에 서로 다른 종류의 정보를 함께 저장하면서 데이터 삽입, 수정, 삭제 과정에서 원하지 않는 문제가 발생하는 현상. 잘못된 테이블 설계로 인해 발생하며, 정규화를 수행하는 주요 이유 중 하나

### 1. 삽입 이상(Insertion Anomaly)

테이블에 새로운 데이터를 삽입할 때 불필요한 데이터까지 함께 입력해야 하거나, 필요한 데이터만으로는 삽입할 수 없는 현상

ex) 학생이 아직 어떤 과목도 수강하지 않았다면 학생 정보만 저장하고 싶어도 기본키가 ( Student ID + Course ID) 로 구성되어 있으므로 ( Course ID )가 필요 ⇒ 결국 실제로 수강하지 않은 과목을 임의로 입력하거나 NULL을 사용해야 하는 문제가 발생

### 2. 갱신 이상(Update Anomaly)

하나의 데이터가 여러 행에 중복되어 저장되어 있어 데이터를 수정할 때 중복된 모든 데이터를 함께 수정해야 하며, 일부만 수정되면 데이터의 불일치가 발생하는 현상임

ex) 한 학생의 학과 정보가 여러 수강 기록에 반복해서 저장되어 있다면 학과가 변경될 때 해당 학생의 모든 행을 수정해야 함 ⇒ 일부 행만 수정할 경우 같은 학생의 학과 정보가 서로 다르게 저장되는 문제가 발생

### 3. 삭제 이상(Deletion Anomaly)

하나의 데이터를 삭제했을 때 삭제하려던 정보와 관계없는 다른 정보까지 함께 삭제되는 현상

ex) 어떤 학생이 마지막으로 수강하던 과목을 취소하여 해당 수강 정보를 삭제하면, 해당 행에 함께 저장되어 있던 학생의 학과 정보까지 사라질 수 있다.. ⇒ 즉, 특정 데이터를 삭제했을 뿐인데 다른 중요한 데이터까지 함께 삭제되는 문제가 발생
