## Index

RDBMS에서 검색 속도를 높이기 위해 사용하는 자료구조로, 테이블의 데이터를 처음부터 모두 확인하는 Full Scan 대신 Index를 통해 필요한 데이터의 위치를 빠르게 찾는 방법

→ 책의 찾아보기와 비슷한 개념으로, 원하는 데이터를 찾기 위한 정보를 별도로 관리하여 전체 데이터를 검색하는 비용을 줄임

### 구조

일반적으로 **B-Tree 계열의 자료구조**를 사용하여 데이터를 정렬된 형태로 관리

Index를 사용하면 검색 조건에 해당하는 값을 Index에서 먼저 찾고, 해당 데이터가 저장된 위치를 찾아 실제 테이블의 데이터를 가져옴

### 장점

- WHERE, JOIN, ORDER BY 등에 사용되는 컬럼의 검색 속도를 높일 수 있음
- 데이터가 많은 테이블에서 Full Scan을 줄일 수 있음
- 기본키는 일반적으로 자동으로 Index가 생성됨
- 여러 컬럼을 묶어서 하나의 Index로 만들 수도 있음

### 단점

Index는 별도의 저장 공간이 필요하며, 데이터가 변경될 때 Index도 함께 관리해야 하므로 INSERT, UPDATE, DELETE 성능이 떨어질 수 있따

따라서 모든 컬럼에 Index를 생성하는 것이 좋은 것은 아니며, 조회가 자주 발생하고 데이터의 중복도가 낮은 컬럼을 중심으로 생성하는 것이 좋음

-> 데이터 중복도가 낮고 수정이 많이 없는 컬럼에 유용함

### DML과 Index

- INSERT : 새로운 데이터를 Index의 정렬된 위치에 추가해야 하므로 Index 구조가 변경될 수 있음
- DELETE : 테이블의 데이터가 삭제되더라도 Index에서 해당 항목을 바로 제거하지 않고 삭제된 상태로 관리하는 경우가 있어 공간과 성능에 영향을 줄 수 있음
- UPDATE : Index 대상 컬럼이 변경되면 기존 Index 정보를 삭제하고 새로운 값을 다시 추가하는 과정이 발생할 수 있어 다른 DML보다 부담이 커질 수 있음

따라서 Index는 조회 성능을 높이는 대신 **데이터 변경 비용과 저장 공간을 추가로 사용하는 방법**이다..라고 생각하면 편하지 않을까 싶음
