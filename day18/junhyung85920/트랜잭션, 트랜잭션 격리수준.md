**Transaction**

DB의 상태를 변화시키기 위해 수행하는 쪼갤 수 없는 업무 처리의 최소 단위

# Transaction의 4가지 특성 (ACID)

Transaction이 안전하게 수행되기 위해 보장해야 하는 4가지 성질

- Atomicity
    - Transaction 내의 작업은 모두 완벽하게 반영되거나, 아니면 아예 반영되지 않아야 한다.
- Consistency
    - Transaction 전후에 DB의 규칙은 항상 일관되게 유지되어야 한다.
- Isolation
    - 둘 이상의 Transaction이 동시에 실행될 때, 서로의 작업에 끼어들거나 간섭할 수 없다.
- Durability
    - 성공적으로 Commit된 Transaction의 결과는 시스템이 고장 나더라도 영구적으로 보존되어야 한다.

# 격리 수준 4단계

## READ UNCOMMITED

- 특징: 다른 Transaction이 commit하지 않은 데이터도 읽는다.
- 문제점: Dirty Read가 발생한다 → 때문에 실무에서 거의 안씀

## READ COMMITED

- 특징: 반드시 commit이 완료된 데이터만 읽도록 허용한다.(Dirty Read 방지)
- 문제점: 하나의 Transaction 안에서 똑같은 조회 쿼리를 두 번 날렸는데, 그 사이에 다른 사람이 데이터를 수정하고 commit하면 두 쿼리의 조회 결과가 달라진다. (Non-Repeatable Read)
- Oracle, PostgreSQL
    - Exclusive Lock을 통해 Non-Repeatable Read 문제를 해결

## REPEATABLE READ

- 특징: Transaction이 시작될 때의 데이터를 스냅샷처럼 기억하며, 같은 Transaction 내에서는 여러 번 조회해도 항상 동일한 결과를 보장한다.
- 문제점: 다른 사람이 기존 데이터를 수정하는 건 막아주지만, 새로운 데이터를 삽입하는 경우 Phantom Read가 발생할 수 있다.
- MySQL InnoDB
    - Next Key Lock을 통해 Phantom Read 문제를 해결

## SERIALIZABLE

- 특징: 가장 엄격한 수준으로, 데이터를 읽는 동안에도 다른 사람들이 절대 접근하지 못하도록 Lock
- 결과: 모든 데이터 불일치 문제가 완벽히 사라지지만, 동시 처리 성능이 최악으로 떨어진다.
